# v2.0.0-beta14 — Volcast 2.0 beta

This is a **pre-release** for testers of the Volcast 2.0 app. It replaces all earlier 2.0.0 betas. The stable line
is unchanged; stay on it unless you were invited to the 2.0 beta.

## What's new

- **Write-right certificates for feed profiles** — a device profile delivered by the profile feed can write to the
  inverter only with a certificate that was signed offline. Without a valid certificate a feed profile stays
  read-only, whatever its status says.
- **Withdrawing a write-enabled feed profile takes effect at once** — when a feed update removes a profile that has
  write rights, or the profile loses its certificate or changes its content, Volcast stops writing with it right
  away. Every inverter it controls is handed back to the owner's settings from before control: the mode, the
  set-points and limits, and the remote-control switch. The hand-back uses the profile that was trusted when control
  started, and the integration entry reloads after it. A hand-back that does not complete is retried every cycle,
  and the reload waits for it. After a restart without that profile, the saved settings are handed back the same
  way instead of being dropped.
- **Profiles are skipped one by one only for schema or engine reasons** — a profile that fails the profile schema,
  or that needs a newer engine than this release, is skipped; the other profiles in the feed still apply. Earlier,
  one such profile rejected the whole feed. A profile with an invalid certificate, or a certificate from an unknown
  key, is not skipped: it stays in the feed as a read-only draft. A feed with an entry that is not an object, has a
  missing, invalid or repeated ID, or has an unsafe or too broad identification pattern is still rejected as a whole.
- **Feeds dated in the future are rejected** — a feed whose generation time is more than 24 hours ahead of the Home
  Assistant clock is rejected as a whole and is not stored, so it cannot block later feeds. A stored feed dated that
  far ahead is also dropped at start.
- **Engine version for profiles** — a profile can declare the minimum engine version it needs (`min_engine`). A
  profile that needs a newer engine than this release is skipped instead of misbehaving.
- **Faster feed updates** — the plan response can hint that the profile feed has changed. The integration then checks
  the feed, at most once every 15 minutes.
- **Three trusted feed signing keys** — the integration accepts feeds signed with any of the three trusted keys.
- **Battery control with a remote-control switch and separate power limits** — the profile format and the control
  engine now support batteries that need a remote-control switch to be turned on before the mode is set, and
  batteries with separate charge and discharge power set-points. This is opt-in per profile; profiles that do not
  declare it behave as before.
- **Repair and onboarding messages for control** — when the inverter control entities are disabled or missing, or
  when the device rejects control writes, Volcast shows a repair issue and a matching onboarding message. The issue
  clears once the cause is fixed. Texts are available in all 13 languages.
- **Price sources from Home Assistant actions** — a buy or sell price source can be a Home Assistant action that
  returns a forecast, instead of an entity. Calls run in the background, with backoff after errors.
- **5-minute price series** — price series with 5-minute intervals are accepted. The 15-, 30- and 60-minute limits
  are unchanged.
- **Price source detection in options** — the options flow detects known price integrations, checks the forecast
  horizon before saving, refuses sensors that only show the current price, and flags a currency mismatch between the
  source and the price currency option.
- **Repair issue when the sell side withholds prices** — when a configured sell source makes the whole price block
  be withheld, a repair issue names that source. It is removed when prices flow again, when the sell source is
  removed, or when the sender stops.
- **Note about tomorrow's sell prices** — when the buy source covers tomorrow but the chosen sell source does not,
  the price options show an informational step before saving. It does not block saving.

## Other changes in this beta

- Production sensors are optional in the setup form; they can be left empty.
- The PV energy sensor help text states that the sensor may be a daily or a lifetime counter.
- Price sources:
  - sell prices are paired across nested interval grids (for example a quarter-hour sell series with an hourly buy
    series);
  - a finer sell series is averaged over each buy interval;
  - the price block is trimmed to the intervals that have both buy and sell prices, or held while a sell price action
    has no fresh result, instead of sending `sell: null`;
  - more price attribute shapes are accepted, and small timestamp jitter is tolerated;
  - sell prices are never paired onto a mismatched interval grid;
  - a price action counts as done only when it returns usable prices;
  - price detection uses the correct domain for one integration, applies a currency rule to one integration, and
    skips gas meters.
- Control:
  - the remote-control switch is held after a failed set-point, and control is blocked while the switch is not
    supported;
  - owner set-points are restored in neutral modes and when control is handed back;
  - control entity reloads are bounded after control entity changes.
- Profiles with overlapping write registers are rejected when they are loaded.
- The German sell price texts use the informal form.

## Behaviour change

- An owner export limit of 30 kW or more, or at the maximum value of the export-limit register (for example a 32-bit
  "no limit" value), is now restored unchanged when control is handed back. Earlier, such a value made the sanity
  check reject each control command.

## Upgrading from an earlier 2.0.0 beta

Update in HACS and restart Home Assistant. Installations on the previous beta keep the last profile feed they
received until they are updated, because that beta does not understand the new profile fields. Your forecast
entities and history are kept.
