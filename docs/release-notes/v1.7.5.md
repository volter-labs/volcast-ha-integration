# v1.7.5 — Production after a data gap

Bug-fix release. No action required.

## Production reporting

- **Energy produced during a gap is no longer attributed to a single hour.** When Home Assistant or the inverter integration was unavailable for a while (a restart, an update, an offline inverter), the energy counted when the readings came back used to land in one hour. The plugin now remembers the last known counter value across silent periods and, after the gap, reports the period the reading covers (up to 36 hours).
- **Hours covered by that report are not re-sent.** The nightly reconciliation no longer sends partial values for hours that a reading after a gap already covered, so they keep the value reported for the whole gap.
- **Closed days can be corrected after a gap.** Once a day is closed, the plugin also sends that day's total calculated from Home Assistant statistics, but only when the statistics for the day are complete, so the day's production can be corrected after a gap. Sending it again gives the same value.

## Sensors

- **Forecast sensors show the data source attribution.** When the forecast uses a weather source that requires a credit, the server supplies the text and the sensors show it unchanged in the standard `attribution` attribute. Without it, nothing changes.
