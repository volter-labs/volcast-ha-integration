# v2.0.0-beta2 — Account pairing and inverter control (beta)

This is a **beta release** building on the discovery preview from v2.0.0b1. Existing setups keep working exactly as before; the new features below are opt-in.

## What's New

### Connect to your Volcast account

Setup now offers "Connect to your Volcast account" — confirm the pairing in the Volcast app or on the Volcast website, and the window closes by itself. An existing discovery-only or API-key entry can be converted the same way, without losing its history.

### Volcast plan in Home Assistant

Once paired, the integration adds a plan card and a "Volcast" panel showing the current and upcoming plan slots, alongside `sensor.*_control_plan` (the plan) and `sensor.*_control_status` (what the integration is doing with it).

### Prices from a Home Assistant entity

If your account's price source is set to Home Assistant (in the Volcast app), you can point Volcast at your own purchase/sale price sensors instead of the built-in providers, in **Options → Energy prices**.

### Inverter control through your inverter's integration (beta preview, off by default)

Volcast can write plan-driven mode and power settings to your inverter, through your existing inverter integration's entities (for example a select for mode and a number for power). Direct Modbus/local connection to the inverter is not available yet — control in this release only goes through another integration's entities.

**This release ships control as a preview, not as live writes.** Writing is enabled per inverter brand only once that brand's profile has been verified against real hardware, and **no brand ships verified in this release** — GoodWe support is pending a live trial. Until a brand is verified, the status sensor always shows what Volcast *would* write (a dry run); nothing reaches the inverter.

Once a brand is verified, nothing is written unless all of the following are also true:

1. **Through the inverter integration (entities)** selected in **Options → Inverter control**
2. Consent given in the Volcast app
3. The `switch.*_control_switch` entity turned on in Home Assistant

Automations you already have on your inverter (for example a clock-triggered schedule) are not detected as "someone else took over" — Volcast treats their effect as ordinary drift from the plan, not as a takeover, so it does **not** pause control for them. Instead, once control is live, Volcast writes the planned value back on its next control cycle (about a minute later). If your own automation is meant to control these settings, turn the Volcast control switch off first — otherwise the two will keep overwriting each other.

If you (not an automation) change a controlled setting by hand while the switch is on, Volcast pauses control for 30 minutes, keeps the setting you changed, and raises a repair. A pause does not survive a Home Assistant restart — after a restart, control resumes immediately even if a pause was in effect before.

When the account revokes consent, the switch is turned off, or the entry is disabled or removed, Volcast returns the inverter to how it was **before Volcast took control** — its baseline mode, export limit and SoC limits — not to the last value Volcast wrote. The one exception: if you had already taken the mode over yourself, Volcast leaves the mode alone and keeps only the last power setpoint it wrote, instead of restoring the older value there too. Entity-mode control and account pairing are both beta; expect rough edges.

### What is sent after pairing

During pairing setup:

- The inverter's make and model (no serial number and no local address — those stay in Home Assistant)
- The price entity id, if a usable price sensor was found

After pairing, on an ongoing basis:

- Live readings roughly once a minute
- Up to 60 days of past consumption history, sent once
- Prices from the entity you selected, when configured
- A control summary — what Volcast is doing or would do, any pause, and how many times a setting was changed outside Volcast (never entity ids or serial numbers)

Everything discovery already read (see the v2.0.0b1 release notes) stays local unless listed above; pairing does not turn discovery into anything more than a read-only scan of what's already listed here.

## What This Does Not Do

- No setting is actually written to your inverter in this release — control runs as a dry-run preview until an inverter brand's profile is verified (see above)
- Even once a brand is verified, nothing is written unless all three control conditions are met
- No time-window / TOU control in this release — the options screen only previews it
- No direct connection to the inverter; control goes through another Home Assistant integration

## Upgrading and Going Back

Update via HACS. If you'd prefer to revert to v1.7.2: if you enabled inverter control, turn off the Volcast control switch (or set **Options → Inverter control → Off**) and confirm the inverter is back in its normal mode first — 1.7.2 has no control logic and cannot undo a write on its own. Then follow the same steps as in the v2.0.0b1 release notes — install 1.7.2 and reload; a paired entry keeps working as a plain forecast entry.
