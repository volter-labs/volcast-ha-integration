# v2.0.0-beta9 — EV charger scheduling

This is a **pre-release** building on v2.0.0b8. The headline change: Volcast can now start, stop and set the current of an EV charger that you already track under **Options → EV charger**, following the charging slots of the Volcast plan.

**Update order:** the matching Volcast server-side update must be live before this build is installed. Without it the plan carries no charger slots, so this version does nothing for the charger (it does not break anything either). Until the server side is available, stay on v2.0.0b8.

## What's New

### Charger scheduling from the plan

- The plan can contain charger slots of two kinds: **forced** (charge now, at the planned power) and **off** (do not charge now). Volcast follows them by writing to the charger integration's own entities: the current setpoint (a `number` entity) and start/stop (a `select` or `switch` entity). Nothing is written to any entity that does not belong to the charger's device.
- In a forced slot Volcast sets the current first and starts charging only after the setpoint write succeeded. The planned power is converted to amps (or kept in watts for chargers that take a power setpoint), within the limits of both the plan and the entity.
- In an off slot Volcast stops a running charge once (for example when the car starts charging by itself on plug-in). If you then start the charge yourself, Volcast treats it as a manual start and does not stop it again (see "Manual stop and start" below).
- Each command is sent once per plan and slot, not repeatedly (a newly calculated plan may send it once more), so a charger that does not start (car full, cable unplugged) is not hammered with commands. Writes to one entity are at least a minute apart.
- Slots that only follow PV surplus are not executed yet; nothing is written for them.

### When Volcast writes to the charger

All of these must be true at the same time, otherwise nothing is written:

- consent given in the Volcast app,
- the Volcast **control switch** is on in Home Assistant,
- plan-only mode is **not** active (if you chose your own controller for the inverter, the charger is left alone too),
- the plan itself allows charger control,
- the charger's status entity is readable.

Turning one of these off in the middle of a charge does not stop or start anything: turning control off leaves the charger in its current state. If the charger was stopped by the plan at that moment, start charging manually if needed.

### Manual stop and start

- Volcast recognises a manual decision in these cases:
  - you or one of your automations stop or start the charge in Home Assistant (the charger's start/stop entity);
  - the charger reports a stop while the plan wants it charging — for example you pressed stop in the charger's own app, on a button or with a card: its status changes from charging to paused or stopped without a recent Volcast command;
  - the charger starts charging while the plan wants it off, after Volcast stopped it in this slot, again without a recent Volcast command.
- Then Volcast stops writing to the charger and reports the event to the cloud once, so the next plan can take it into account. Commands resume only with a plan generated after your change. A later manual change replaces the earlier one; the last decision wins.
- **Not** treated as manual:
  - the end of charging (finished, complete, car full);
  - charger errors and an unavailable charger;
  - a pause on the car side;
  - unplugging;
  - a change within about 30 seconds of a Volcast command;
  - the car starting to charge by itself on plug-in or on its own schedule before Volcast stopped it. Such a charge in an off slot is stopped once.
- Status texts are recognised from English words (for example `Charging`, `Paused`, `Stopped`, `Finished`). A charger reporting other words is only recognised through its start/stop entity.
- If the pause lasts more than six hours without a new plan, one warning is logged. Volcast does not resume on its own.

### Emergency rule

If the Volcast cloud has not answered for over about 90 minutes, Volcast does not leave the car uncharged: when the planned ready time gets close enough that the remaining energy still fits at full power (with a safety margin), it starts charging at full power. Limits of this rule:

- It applies only when the cloud explicitly allowed it for the current plan. The cloud does not allow it when you paused charging or chose a PV-only mode, and a server that does not send this permission disables the rule.
- It runs only inside the gates above and never during a manual pause.
- It can only start a charge, never stop one.
- It does not wait for the first answer for a few minutes after Home Assistant starts.
- It uses the full current of the charger (within the plan and entity limits). It does not know the grid connection limit, so with a large household load check that the main fuse can take it.
- The remaining energy is the value from the last plan, so it keeps charging until the car is full or a fresh plan arrives, also after the ready time.
- The state is reported to the cloud once the connection is back.

## Known Limitations

- A charger's "charging" state is recognised from English status words (for example `Charging`); status texts in other languages are not recognised, which errs on the safe side (no stop commands, one start per plan).
- Only one charger setpoint and one start/stop entity per charger are used; other controls of the charger are left alone.
- The known limitations of v2.0.0b8 still apply.

## Upgrading

Make sure the server-side update is live, then update via HACS and restart Home Assistant. Choose the charger under **Options → EV charger** (the charger integration must already be set up and found by discovery). Installing or updating by itself does not write anything to the charger; writes need the consent in the Volcast app, the control switch in Home Assistant and charger control enabled in the plan. When all of these are already in place, the stored plan is followed from the first cycle after the restart.
