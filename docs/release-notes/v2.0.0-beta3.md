# v2.0.0-beta3 — Direct connection to the inverter (beta)

This is a **pre-release** building on v2.0.0b2. Existing setups keep working exactly as before; everything below is opt-in.

## What's New

### Direct connection over the local network

Volcast can now talk to a supported inverter directly on your local network, without another Home Assistant integration in between:

- **GoodWe** (ET/EH/BT/BH family) — over UDP (the same protocol as the inverter's Wi-Fi/LAN module) or Modbus TCP
- **Deye** three-phase hybrids (SUN-xK-SG family) — through a Solarman data logger or Modbus TCP
- Either brand behind an **RS485 ↔ TCP gateway** (Modbus RTU over TCP)

### Search for the inverter

**Options → Installation details → Search for the inverter on the local network** looks for inverters that answer on the local network and reads only their identification. You pick the inverter from a list (no addresses in the list), or enter its local IP address yourself. A manually entered address is checked the same way before it is saved.

### Inverter sensors

With a direct connection, Volcast adds its own sensors read from the inverter: battery state of charge, temperature, voltage and current, battery, PV, grid, load and inverter power, lifetime PV and grid energy counters (usable in the Energy dashboard), the inverter mode, and, as diagnostic sensors, the power, export limit and minimum state-of-charge settings plus the share of requests that got no answer. Readings refresh every 10 seconds by default (5–60 s in **Installation details**). A sensor becomes unavailable when its reading is older than three refresh periods.

### Read-only test connection

For an inverter whose direct control is **not verified yet**, **Installation details → Read-only test connection** connects to it, shows the sensors above, and shows what Volcast *would* write — without ever writing. It is the step used to verify a brand on live hardware. It is refused while Volcast still controls the inverter from an earlier session, and it cannot run together with control through the inverter integration.

## Direct control ships disabled

**Direct control (writing to the inverter) is not available in this release.** It is enabled per brand only after that brand's register map has been verified on a live inverter, and **both built-in direct profiles (GoodWe and Deye) are still draft**. Choosing **Options → Inverter control → Directly over the local network** therefore stops with "Direct control is not available for this inverter yet". The read-only test connection is what you can use today.

Once a brand is verified, nothing is written unless all of these are true at the same time: direct control is selected in the options, you have given consent in the Volcast app, the Volcast control switch is on, the inverter's identity at the saved address is confirmed, and no other client is using the inverter.

## Safety Behaviour (direct connection)

These rules apply as soon as a brand is verified; the test connection never writes at all.

- **Every write is read back.** Volcast reads the register before and after each write and records only what the inverter actually holds. A refused write is not repeated over and over; an unclear result is resolved by the next reading.
- **Daily limit on setting changes.** Writes to the inverter's memory are counted per setting and in total over a rolling 24 hours, and the count survives restarts. When the limit is reached, further changes wait; a forced charge or discharge is first returned to the inverter's normal mode instead of being left running. Returning the inverter to its own settings is never blocked by the limit (it is counted).
- **Returning control.** When consent is withdrawn, the control switch is turned off, or the entry is disabled or removed, Volcast returns the inverter to how it was before Volcast took control — its normal mode, and the limits and time-of-use programs it had then — and confirms each value by reading it back before letting go. A plain restart or reload does not return anything.
- **You change a setting yourself.** A single change is treated as drift and the planned value is written back on the next control cycle. If the same setting is changed outside Volcast again within 30 minutes, Volcast pauses for 30 minutes, keeps your value, raises a repair notification, and does not write that setting again until its plan for it changes.
- **Another client uses the inverter.** If another Home Assistant integration is configured for the same inverter address (or its address cannot be determined), direct connection is refused — turn that integration off first. If signs of another client appear while connected, Volcast stops writing its plan, reads less often and raises a repair notification; returning the inverter to its own settings still works.
- **A different device at the saved address.** Volcast checks the inverter's identity at start, after reconnects, hourly on UDP, and before writing. If a different device answers, reading and control stop and a repair notification asks you to search for your inverter again. No write, including a return to baseline, goes to a device whose identity is not confirmed.

## What Is Sent and Stored

Stored in Home Assistant only (entry options and Home Assistant storage):

- The inverter's local address, port, Modbus unit ID and, for Solarman loggers, the logger serial number
- A device fingerprint — a keyed hash of the inverter's identification, computed with a random value created once per Home Assistant installation (the random value stays in Home Assistant storage)
- What the search found: which settings exist and can be read back, and the rated power

Sent to your Volcast account (paired entries):

- The same readings as before, now taken from the inverter's registers, plus the inverter mode name
- The profile id, that the connection is direct, which settings Volcast can control, the rated power, and connection counters (connection type, status, number of timeouts and unexpected frames, whether the write limit was hit)
- During pairing: the inverter's make and model, rated power, the settings found, and which control options are available

**Never sent:** the local address or port, the inverter's serial number, the logger serial number, the device fingerprint or the random installation value.

The diagnostics file has a direct-connection section with the same counters and status and no address, serial number, logger serial, fingerprint or installation value. Only while the **read-only test connection** is on, it also contains the last raw frames read from the inverter — with serial-number registers and the logger serial zeroed and checksums recalculated — so they can be shared to help verify a brand.

## What This Does Not Do

- No serial port: RS485 inverters need an RS485 ↔ TCP gateway
- No addresses outside the local network, and no host names — only a local IP address is accepted
- No automatic scanning in the background: the network is searched only when you ask for it in the options, or once during pairing when no inverter integration was found in Home Assistant
- No writes in this release (see "Direct control ships disabled")

## Known Limitations

- **Single-phase Deye** inverters use a different register layout and are not identified; the search reports that no inverter was found.
- **Solarman data loggers**: frame handling follows the public protocol description; behaviour with real loggers (for example with a vendor cloud connected at the same time) is not verified yet.
- **Deye writes**: the write function and the exact meaning of the time-of-use enable register are pending a live trial.
- **GoodWe**: on some models the upper state-of-charge limit cannot be read back, so Volcast does not set it over a direct connection.
- A 30-minute pause does not survive a Home Assistant restart.
- The "timeouts" diagnostic sensor counts since the connection started, not over a recent window.

## Upgrading and Going Back

Update via HACS. To go back to v2.0.0b2: if you ever used **direct control**, first **turn off the Volcast control switch** and wait until the Volcast status sensor shows that the inverter was returned to its settings from before Volcast — b2 does not know about direct control and cannot return those settings for you. Entries that use control through the inverter integration are recognised by b2 as they are. Then install b2 and reload.
