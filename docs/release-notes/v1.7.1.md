# v1.7.1 — Resilience, force sync, and setup guardrails

First stable release since v1.6.1. Everything from the 1.6.2 and 1.7.0 pre-releases plus fixes found while dogfooding them.

## Setup

- **API key sanity check** — the setup dialog now rejects a malformed key before contacting the server, with a specific message. Pasting the shortened preview from the app (`vk_xxxx...xxxx`) tells you to use the Copy or Share button; anything else that is not a 67-character `vk_` key gets a plain "not a Volcast API key" hint. The setup text points to *Settings > API Key*, matching the app.

## Production tracking

- **Counter baseline survives an HA restart** — the daily energy baseline is persisted, so a restart mid-day no longer loses or double-counts the hours around it.
- **Submissions capped at the backend limit** — retry batches are split at 24 readings, so a long backlog drains instead of being rejected as a whole.
- **Force sync** — *Sync production now* button on the device page and the `volcast.sync_production` action (optional `date`) reconcile yesterday and today from Recorder statistics on demand. Safe to repeat.
- **Startup self-heal covers today** — on every HA start the integration reconciles yesterday *and* today, so a gap from a mid-day restart heals immediately instead of at 00:30.

## Forecast and Energy Dashboard

- **HAEO compatibility** — `pv_estimate` (kW) on `detailedForecast` entries.
- **Past-day forecast history retained** in the Energy Dashboard.
- **Default poll interval 60 min** — the server cache refreshes hourly, so polling more often had no value.

## Upgrading

Update via HACS. No configuration changes required. Users on 1.7.0-beta1 can switch off "show beta versions" after updating.
