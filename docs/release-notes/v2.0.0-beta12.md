# v2.0.0-beta12 — control setup fix and pairing reliability

This is a **pre-release** building on v2.0.0-beta11. It contains fixes only.

## Fixes

### Control setup
- Inverter control could fail to start with `Volcast control could not be set up (AttributeError)` on installations where the inverter work-mode select entity is available at startup (for example GoodWe on the built-in Home Assistant `goodwe` integration). Forecast and production reporting kept working, but live readings, the battery plan and prices did not. Control now starts normally.
- When control setup fails for any other reason, the log now includes the full error details.

### Pairing
- The pairing reporter and poller stop as soon as the Volcast cloud reports the session as no longer live, and a closed session's stored data is cleared so the next pairing starts clean.

### Other
- Sensors keep their last data for a few failed refresh cycles on transient network errors.
- No more deprecation warnings about `DeviceEntry.config_entries` on Home Assistant 2026.10.

## Upgrade notes
- Update through HACS and restart Home Assistant. Existing paired entries keep working; there is no need to pair again.
- Once control starts, an inverter in a non-neutral work mode (for example `eco`) shows the existing work-mode notice in Repairs. This is expected.
