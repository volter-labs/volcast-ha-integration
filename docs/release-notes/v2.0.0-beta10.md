# v2.0.0-beta10 — EV charger preview, signed brand profiles, operation mode check

This is a **pre-release** building on v2.0.0-beta6. Versions 2.0.0-beta7 to beta9 were not published; everything they contained ships in this build, together with the changes listed below. For the full detail of the earlier changes see the v2.0.0-beta8 and v2.0.0-beta9 notes.

## Highlights since v2.0.0-beta6

- **Inverter control onboarding** (from beta8): a recommended control path, a manual entity map with a preview step, automatic per-device verification before the first write, detection of competing controllers, and a control switch that follows the consent you give in the Volcast app.
- **Eight draft brand profiles** (from beta8): Huawei, Sungrow, SolaX, Sofar, Solis, FoxESS, SolarEdge and Fronius, for the read-only test connection. GoodWe ET also reads energy counters and battery limits.
- **Inverter operation mode check** (from beta9, GoodWe ET): the operation mode is read and reported, and a Repairs issue appears when it is not General. Read-only; nothing is written to the inverter.
- **Plan summary sensor** (new): see below.
- **EV charger scheduling** (new, **preview, requires opt-in**): see below.
- **Signed brand-profile feed** (new): see below.
- **Regex safety for profiles** (new): see below.
- **Discovery report** (new): see below.

## What's New

### Plan summary sensor

- A new **Plan summary** sensor describes the current battery plan in plain words, in your Home Assistant language, for example "Now: charging from the grid until 14:00, then self-consumption". It shows words and times only, no power values.
- The Volcast plan card no longer shows setpoints the plan does not set.

### Signed brand-profile feed

- Volcast can now receive new brand profiles between releases. The feed is cryptographically signed; the integration verifies the signature, refuses older or malformed feeds and keeps the last good set when a check fails. It checks about once a day.
- Profiles from the feed are always **read-only drafts**: they can be used for discovery, recommendations and the read-only test connection, but they never write to your inverter, and a profile shipped inside the integration always takes priority over a feed profile with the same id.
- When a new profile matching your inverter appears, a Repairs notice tells you it is ready to try. A profile that a later feed withdraws disappears again, and any control state saved through it is dropped with a Repairs notice instead of being restored through a profile that no longer exists.
- The feed needs the `cryptography` package (installed automatically with the integration).

### Profile regex safety

- Patterns in brand profiles are restricted to a safe subset and checked with a cost model, so a profile can no longer make Home Assistant spend unbounded time matching a device name. Over-long device names count as no match, and unsafe or invalid patterns make the profile fail validation.

### Discovery report

- On request from the Volcast cloud, the integration sends a short report of the inverter integrations and devices it found, which helps Volcast add support for more brands. Identifiers are masked, it runs in the background, it stops when the integration is unloaded, and it never delays control.

### EV charger scheduling (preview, requires opt-in)

This is a preview. It does nothing unless the matching server-side feature is enabled for your account, you gave consent in the Volcast app, you chose a charger under **Options → EV charger**, and the Volcast control switch is on.

**Update order:** the matching Volcast server-side update must be live before this build is installed. Without it the plan carries no charger slots, so the charger part does nothing (it does not break anything either).

- The plan can contain charger slots of two kinds: **forced** (charge now, at the planned power) and **off** (do not charge now). Volcast follows them by writing to the charger integration's own entities: the current setpoint (a `number` entity) and start/stop (a `select` or `switch` entity). Nothing is written to any entity that does not belong to the charger's device.
- In a forced slot Volcast sets the current first and starts charging only after the setpoint write succeeded. The planned power is converted to amps (or kept in watts for chargers that take a power setpoint), within the limits of both the plan and the entity.
- In an off slot Volcast stops a running charge once. When the car starts charging by itself on plug-in, Volcast waits about three minutes before stopping it. If you then start the charge yourself, Volcast treats it as a manual start and does not stop it again (see "Manual stop and start" below).
- Commands are not repeated, so a charger that does not start (car full, cable unplugged) is not hammered with commands: a start or a stop is sent once per plan and slot. A new plan arrives when the cloud recalculates it — after it accepted a change you made, after a request from Home Assistant, or on other changes, not on a fixed schedule — so a car that does not take power (for example it waits for its own schedule) gets a start again with every new plan during a charging slot. If charging stops without a Volcast stop, Volcast pauses instead of restarting it (see below).
- Writes to one entity are at least a minute apart.
- Slots that only follow PV surplus are not executed yet; nothing is written for them.

### When Volcast writes to the charger

All of these must be true at the same time, otherwise nothing is written:

- consent given in the Volcast app,
- the Volcast **control switch** is on in Home Assistant,
- plan-only mode is **not** active (if you chose your own controller for the inverter, the charger is left alone too),
- the plan itself allows charger control,
- the charger's status entity is readable.

Turning one of these off in the middle of a charge does not stop or start anything: turning control off leaves the charger in its current state. If the charger was stopped by the plan at that moment, start charging manually if needed.

### Manual stop and start, and charging that stops by itself

- Volcast pauses (sends no commands at all, also no start) when:
  - you or one of your automations stop the charge in Home Assistant during a charging slot, or start it during an off slot (the charger's start/stop or status entity, changed with a Home Assistant user or automation);
  - the charger stops charging during a charging slot (or during the emergency rule) without a recent Volcast stop: paused or stopped, "charged" or finished, an error, the charger becoming unavailable, unplugging. Many chargers show every stop as "charged", also a stop from their own app, a button or a card;
  - the charger starts charging during an off slot after Volcast stopped it there, without a recent Volcast command.
- The pause starts at that moment and is kept across Home Assistant restarts. It ends only with a new plan generated after it started — after a manual stop or start only with a plan received after the cloud accepted that event, so a plan calculated before the cloud knew about your stop does not restart charging — or with a new charging session. A recalculated plan from before the pause, a moved slot or the next slot do not end it. Every telemetry upload carries the start of the pause, and the cloud recalculates the plan after it (within about half a minute when the cloud is reachable). If the new plan still wants charging — for example after you tap **Resume** in the app, or when the server moved the slot — Volcast sets the current and starts again.
- Volcast also reports a **manual stop** to the cloud (once), so the plan can take it into account, when:
  - you stopped the charge in Home Assistant; or
  - the charger shows paused, stopped, "charged" or finished, the plan is current (the cloud answered within about 90 minutes) and still needs more than about 0.5 kWh to reach the target.
  Errors, an unavailable charger, unplugging, a car-side pause and "waiting for authorization" pause Volcast without a manual stop. So does a stop within about 30 seconds of any Volcast write (also a current change), because it may be the charger's reaction to that write; the next plan then does not know about the stop and may start charging again.
- A car that stops at its own charge limit (for example 80 %) while the plan still expects energy looks exactly like a stop from the charger's app: Volcast reports a manual stop and pauses until the next plan. This is accepted; the next plan reflects the real state.
- A later change you make in Home Assistant replaces the earlier one; the last decision wins.
- The charger's start/stop entity counts only when the change comes from a Home Assistant user or automation. Changes of that entity without one are ignored: on some chargers it is a one-shot control that returns to "No operation" right away, and the charger sets it by itself (for example "Stop charging" at the very moment a charge starts, or "Start charging" when the cable is unplugged).
- **Not** treated as a stop or start: a change within about 30 seconds of a Volcast stop; the car starting by itself on plug-in or on its own schedule before Volcast stopped it (such a charge in an off slot is stopped once, after about three minutes).
- Status texts are recognised from English words (for example `Charging`, `Paused`, `Charged`, `Finished`).
- If the pause lasts more than six hours without a new plan, one warning is logged. Volcast does not resume on its own.

### Emergency rule

If the Volcast cloud has not answered for over about 90 minutes, Volcast does not leave the car uncharged: when the planned ready time gets close enough that the remaining energy still fits at full power (with a safety margin), it starts charging at full power. Limits of this rule:

- It applies only when the cloud explicitly allowed it for the current plan. The cloud does not allow it when you paused charging or chose a PV-only mode, and a server that does not send this permission disables the rule.
- It runs only inside the gates above and never during a manual pause.
- It can only start a charge, never stop one.
- It does not wait for the first answer for a few minutes after Home Assistant starts.
- It uses the full current of the charger (within the plan and entity limits). It does not know the grid connection limit, so with a large household load check that the main fuse can take it.
- The remaining energy is the value from the last plan, so it keeps charging until the car is full or a fresh plan arrives, also after the ready time.
- The state is reported to the cloud once the connection is back.

## Known Limitations

- A charger's "charging" state is recognised from English status words (for example `Charging`). Status texts in other languages are not recognised, which errs on the safe side (no stop commands, no pause, one start per plan).
- A start from the charger's own app, button or card in an off slot counts as manual only if Volcast stopped the charger in that slot since the last plan update. Otherwise Volcast may stop that charge once; starting it again is then recognised as manual.
- A charge that stops by itself always pauses Volcast until the next plan, also when the car only reached its own charge limit, and also when the charger integration becomes unavailable for a moment while charging. Without a connection to the cloud the pause lasts until the connection is back.
- A change made outside Home Assistant on a charger whose status does not leave "charging" (only the start/stop entity changes) is not recognised.
- A stop from the charger's app while its integration is briefly unavailable (charging → unavailable → charged) pauses Volcast without a manual stop, so the next plan may start charging again.
- A stop from the charger's app while Home Assistant restarts or reloads is not seen; the next plan may start charging again.
- A plan whose calculation started a few seconds before the cloud recorded your manual stop, and which arrives after the cloud accepted it, does not know about the stop and may start charging again until the following plan (usually within a minute).
- If the cloud's answer to the upload with your manual stop is lost while a newer plan already arrived, the pause restarts at the moment the upload is accepted, and the next upload asks the cloud for a fresh plan; the pause then ends within about a minute.
- Only one charger setpoint and one start/stop entity per charger are used; other controls of the charger are left alone.
- The known limitations of v2.0.0-beta9 still apply.

## Upgrading

Make sure the server-side update is live, then update via HACS and restart Home Assistant. Choose the charger under **Options → EV charger** (the charger integration must already be set up and found by discovery). Installing or updating by itself does not write anything to the charger; writes need the consent in the Volcast app, the control switch in Home Assistant and charger control enabled in the plan. When all of these are already in place, the stored plan is followed from the first cycle after the restart.
