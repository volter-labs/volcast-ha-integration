# v2.0.0-beta6 — GoodWe direct control

This is a **pre-release** building on v2.0.0b4. The v2.0.0b5 changes (safer register reads and write checks on the GoodWe Wi-Fi module, see `docs/release-notes/v2.0.0-beta5.md`) were not published as a separate release and are included here. It turns on direct control of a GoodWe ET/EH/BT/BH inverter over the local network (registers through the inverter's Wi-Fi module, UDP) and adds the safeguards that direct control needs. The register map and write behaviour were verified on a live **GW8KN-ET** over the Wi-Fi module (UDP). Writes are also enabled over Modbus TCP and over an RS485 ↔ TCP gateway (Modbus RTU framing): these use the same registers, but have not been tried on hardware yet. Other ET/EH/BT/BH models share the same register map but have not been tried yet; the inverter search detects registers a model does not have, and Volcast does not use them.

## What's New

### GoodWe direct control is available

- The built-in GoodWe profile is now marked verified for the register path. A GoodWe inverter found on the network can be set to the Direct control mode in **Options → Inverter control → Directly over the local network** (and from the Volcast app when pairing).
- Deye stays a draft: only the read-only test connection is available for it, and no register writes are made.
- If you turned on the read-only test connection for a GoodWe inverter in an earlier beta, it stays on (and can still be switched off in **Installation details**) — nothing is written while it is on. To let Volcast control the inverter, turn the test connection off and choose **Directly over the local network** in **Inverter control**.

### New safeguards for direct control

These are new in this version. "Neutral mode" below means the inverter's normal self-use mode (GoodWe "auto"); it is **not** the same as returning the inverter to the settings it had before Volcast took control (that full return still happens when you withdraw consent, turn the control switch off, or disable or remove the entry).

- **Neutral brake.** When a control cycle cannot run the plan safely — no plan, a stale or missing inverter reading (for example after losing the connection to the inverter), an error during the cycle, or another client on the inverter's connection — and the inverter is still in a forced mode set by Volcast, Volcast writes the neutral mode only. With a stale reading this write is sent only after a fresh read confirms the inverter is still in Volcast's mode. Short one-cycle glitches (a single missing temperature or an implausible state-of-charge jump) brake only if they repeat on the next cycle. A state-of-charge reading that jumps and then returns to its earlier value, or that keeps its new value on the next reading, is not counted as a second jump.
- **Neutral mode at the battery reserve during a pause.** While control is paused, a discharge mode set by Volcast is replaced with the neutral mode once the battery reaches the plan's reserve. A mode you chose yourself is never overwritten, and no other writes are made during the pause.
- **Actions without a usable setting fall back to neutral mode.** If a setting needed for an action has no register on the inverter, cannot be read, or was not confirmed by the inverter search, the action runs in the neutral mode instead. A register that rejects a write is treated as unsupported only when it rejects a write a second time, also if the connection was re-established in between. If the inverter's mode register itself is not usable, direct control does not run at all and a repair notification is raised. An unsupported upper state-of-charge limit does not block anything.
- **Live sell setpoint.** In a sell slot the export setpoint is recalculated from the inverter's own reading (battery discharge power from the plan plus PV production minus house load, capped at the rated power and the export limit). If PV or house load is missing, stale or implausible, the slot runs in the neutral mode. A single invalid sample is bridged with the last valid reading for one cycle, only if that reading is recent (at most about two and a half minutes old). After a restart, or a long gap without valid readings, a PV reading that would push the setpoint up to its cap (the rated power or the export limit, whichever is lower) is used only after a second reading confirms it.
- **Neutral mode when Home Assistant stops, and on unload or reload of the entry.** If the inverter is in a forced mode set by Volcast, Volcast tries to write the neutral mode before Home Assistant shuts down, and when the entry is unloaded or reloaded. This is best effort within a 10-second budget, not a guarantee: if the inverter does not answer in time, it keeps its last mode and an error is logged. Control resumes after the restart or reload. **This also applies to entity mode** (control through the GoodWe integration): from this version, stopping Home Assistant moves the inverter out of a forced charge or discharge set by Volcast. Removing the entry still returns the inverter to its settings from before Volcast; if that is not possible, a repair notification is raised.

Writes are still checked by reading the value back, and the daily write limit from earlier betas still applies.

### Exclusive use of the Wi-Fi module

The Wi-Fi module of a GoodWe inverter serves one local client reliably. Volcast must be its **only** local client: other Home Assistant integrations, the manufacturer's app on the local network and other energy controllers talking to the same module cause timeouts and mismatched replies. Volcast refuses an address that another enabled integration entry already uses.

## Writes start only after you choose Direct mode and give consent

Writes to the inverter start only when all of these are true: Direct control mode is selected for the entry, you have given consent in the Volcast app, and the Volcast control switch in Home Assistant is on. Updating alone does not change an existing setup that uses entity mode or has control off.

## Known Limitations

- **The safeguards only work while Home Assistant is running.** If Home Assistant crashes or hangs, or the host loses power or network, while the inverter is in a forced mode (charging from the grid or selling), the inverter stays in that mode until Home Assistant is back and reconnects. Keep this in mind before enabling control, and check the inverter if Home Assistant has been down.
- On some GoodWe models the upper state-of-charge limit cannot be read back; Volcast then does not set it.
- The known limitations from v2.0.0b4 and v2.0.0b5 still apply. In entity mode, **selling needs a house-consumption reading**: if there is no usable house-consumption sensor and no earlier valid reading since Home Assistant started, a sell slot exports nothing (0 W).

## Upgrading and Going Back

Update via HACS and restart Home Assistant. To go back to v2.0.0b4, turn off the Volcast control switch first and wait until the status sensor shows that the inverter was returned to its own settings.
