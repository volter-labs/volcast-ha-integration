# v2.0.0-beta5 — Safer register reads and write checks

This is a **pre-release** building on v2.0.0b4. It changes how Volcast talks to a GoodWe inverter over the local network (UDP) when the read-only test connection or the register path is used. It does **not** turn direct control on.

## What's New

### Register reads and write checks on the inverter's Wi-Fi module

The Wi-Fi module of a GoodWe inverter answers slowly and unevenly: replies can arrive late, a reply to an earlier request can be repeated for the next one, and replies meant for other clients can show up. Replies carry no register address, so a reply of the right length is accepted as the answer. In this version:

- Reads on the module are spaced 300 ms apart (was 50 ms), and datagrams waiting in the socket are dropped before every request.
- Consecutive reads use replies of different lengths, so a repeated earlier reply no longer passes as the next answer. Registers that exist only as a single word are read between longer blocks.
- A "register not supported" answer, and the value read before a write, are accepted only when a second read confirms them. A single stale or foreign reply can no longer switch a feature off or make a write look successful.
- Features the inverter does not have (for example the maximum state-of-charge register on some models) are detected by the probe and are not polled again.
- After a write, a setting that the inverter applies slowly (for example the minimum state of charge) is read again after a short wait before the write is judged. A write is reported as denied only if the value is still unchanged after that.
- The whole sequence for one setting (reads, write, read-back) has exclusive use of the connection, so the regular polling cannot interleave with it.
- A write that gets no reply is sent once more. Both sends count against the daily write limit, and the second send is skipped when the limit is used up (a return to the inverter's own settings is always allowed to repeat).

### Diagnostics

The transport statistics now include the number of repeated writes.

## Direct control stays disabled

Direct control over the local network (writing to registers) is **still not available**: both built-in direct profiles (GoodWe and Deye) remain draft. Control through the GoodWe inverter integration (entity mode) from v2.0.0b4 works as before. Updating does not start any writes.

## Known Limitations

The known limitations from v2.0.0b4 still apply. In particular, **selling needs a house-consumption reading**: if there is no usable house-consumption sensor and no earlier valid reading since Home Assistant started, a sell slot exports nothing (0 W).

On a GoodWe inverter's Wi-Fi module, other clients that poll the same module (the manufacturer's app or cloud link, other Home Assistant integrations, other energy controllers) cause timeouts and mismatched replies. Volcast refuses an address that another enabled integration entry already uses.

## Upgrading and Going Back

Update via HACS and restart Home Assistant. To go back to v2.0.0b4, turn off the Volcast control switch first and wait until the status sensor shows that the inverter was returned to its own settings.
